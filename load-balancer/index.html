Load Balancing Explained

A load balancer distributes incoming application traffic across multiple targets to improve availability and scalability.

Concepts and architecture

How it works


           Users
              |
              v
      Application Load Balancer
              |
       +------+------+
       |             |
       v             v
    EC2 - A        EC2 - B
       |             |
       +------+------+
              |
       Application data

The load balancer receives requests, evaluates its routing rules and sends traffic to healthy registered targets.

Important components

Listener

Checks for connection requests on a configured protocol and port, such as HTTP on port 80 or HTTPS on port 443.

Target Group

Defines the targets receiving traffic, such as EC2 instances, and the protocol and port used to reach them.

Health Checks

Periodically test target health so unhealthy targets can be excluded from normal traffic routing.

Auto Scaling

Can add or remove EC2 instances as demand changes. A load balancer and Auto Scaling solve different problems.

Request flow

1. A user sends a request to the load balancer. 2. A listener accepts the request. 3. Routing rules select a target group. 4. Traffic goes to a healthy target. 5. The application returns a response to the user.

Why use a load balancer?

Availability

Reduce dependence on a single application server.

Scalability

Distribute requests among multiple targets as traffic grows.

Health monitoring

Route requests away from targets that fail health checks.
