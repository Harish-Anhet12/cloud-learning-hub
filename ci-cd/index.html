CI/CD Pipeline

Learn how code changes move from a developer's laptop through automated checks to a deployed application.

Continuous Integration · Continuous Delivery

How a CI/CD pipeline works

01 · Source

Git & GitHub

Developers commit changes to Git and push them to a shared repository such as GitHub.

02 · Build

Build

Automation prepares the application, installs dependencies and creates a deployable artifact or container image.

03 · Test

Automated Tests

Run unit tests, integration tests and quality checks to catch problems before release.

04 · Deploy

Deployment

Release the verified version to a test or production environment using a controlled process.

Tools used in CI/CD

Git

Tracks source-code changes and supports branching, merging and collaboration.

GitHub

Hosts repositories and supports pull requests, reviews and workflow automation.

Jenkins

Automates pipeline stages using jobs and pipeline definitions, including a Jenkinsfile.

AWS

Provides infrastructure and services where applications and deployment workflows can run.

Why CI/CD matters

Consistency: repeat the same deployment steps. Faster feedback: discover errors earlier. Safer releases: test changes before deployment. Traceability: track which code version was released.
